# Project and evidence format v1

A MAR project is a ZIP, never unpacked by Studio. Its members are project.json, anchor.json, preview.png, audit.jsonl, audit.sqlite, snapshots/<sha256>.json, assets/<sha256>.<type>, artifacts/<sha256>, and manifest.json as applicable. The manifest maps each other member's exact bytes to lowercase SHA-256. The bundle duplicates the source/snapshot/ledger files alongside the editable project, provides named exports and the printable report, and contains a copy of the dependency-free verifier. The bundle's own ZIP digest and the manifest's own digest are excluded. The source bytes are kept by digest, so choosing an identical source again reuses the first record.

The executable schema is in marstudio/integrity.py. Every loaded state, object, archive member, and replayed transition is bounded and validated. Layer and artifact IDs are UUID4 hex strings. Coordinates, crop fractions, and styles are numeric; colors are #RRGGBBAA. The paper and viewport use millimeters. Fonts use points; rich text stores code-point spans for inline bold/italic. Appearance comes from state and bundled DejaVu Sans. Groups are hierarchical ordering/visibility/opacity/lock containers; child geometry uses page coordinates. Out-of-page parts are clipped. Linked connectors attach to object bounding frames and recompute when those layers move. Their exported SVG counterparts are regular vectors and do not retain live linking.

Each session gets a new UUID. The SQLite ledger stores canonical event JSON in BLOB rows keyed by monotonically increasing project sequence. Triggers reject updates, deletes, and nonconsecutive inserts. The JSONL contains the same canonical bytes per row followed by LF. Each record has project and session IDs, a sequence number, observed UTC and local offset, action, origin, optional self-declared operator name, affected layer/source IDs, details, ordered before/after patch entries, environment, and predecessor/current digest. Naming an operator records a declaration, not an identity verification.

## Exact chain

Canonical JSON is Python's UTF-8 encoding of json.dumps with sort_keys=True, ensure_ascii=False, allow_nan=False and separators=(",", ":"). Duplicate keys, invalid Unicode, nonfinite values, and unbounded structures are rejected. Each event's hash is SHA-256 of this representation after removing only its hash field. Its previous field is the preceding event hash or 64 zeros for the first. Snapshot hashes are SHA-256 of the complete canonical project state. A snapshot is referenced from its event; equal states may share a snapshot. Undo/redo append state transitions and name the sequence they reverse/reapply. Nothing is deleted from history. Tool steps, including undo/redo, imports, checkpoints, and alignment, are distinguished from manual UI mutations.

The anchor is a canonical object with project, count, head and state (hash of final canonical state). It detects missing trailing entries when compared against the saved anchor. Verification checks member hashes, event numbering/links/digests, replayed before-values, each referenced state snapshot, the final state, SQLite/JSONL logical equality, exact source bytes, original PNG dimensions, and archived export bytes. The bundle verifier also checks that exposed copies match the project. Exported reports refer to the state immediately before their own PDF was added to the archive. A successful bundle verification does not validate the claims typed inside it.

Anyone with sufficient local access could rewrite the entire package and produce consistent hashes. Save external anchor writes a shareable JSON receipt locally; it never connects to a timestamp service. Keep the head with an independent custodian if that matters. Pass the independently retained digest using --expected-head. An external timestamp can corroborate when a specific digest existed, not who composed the work. The app does not create Git commits or record the screen. This is not signed, encrypted, or a verified timestamping mechanism.

Schema v1 is the first release, so there is no older native file to migrate. Its version gate rejects unknown versions. A future migration must preserve and verify the original canonical bytes before adding a tool-labeled migration transition; never rehash past events as a migration shortcut.

## Filesystem and parsing boundaries

- Saves and outputs write to a sibling temporary file, flush/fsync and use atomic replace. POSIX also syncs the destination directory. Abrupt failure before replacement retains the previous valid save and may leave a .pending sibling file. A separate local recovery copy is written after a short idle interval. Edits made after the last recovery write can be lost on abrupt exit. Do not edit the same project in two instances and expect a history merge.
- ZIP checks reject traversal, drive/UNC paths, reserved device names, symlinks, duplicate and case-conflicting names, file/directory collisions, encryption, and unsupported compression. Limits: 128 MiB per member, 512 MiB expanded per archive, 48 MiB for selected source files, 24 MiB per JSON document, and 75 million pixels per decoded/rasterized image. The editor has 20,000 events and 3,500 layers as upper limits; practical responsiveness drops earlier for unusually large histories or artwork. Bigger posters can be exported as vector files.
- SVG is export-only. No active SVG, entity resolution, URLs, scripts, SVG/fonts in imports, or HTML paste parser is enabled. PNG decoding is explicitly restricted to PNG with dimension and allocation bounds. Markdown and text are plain preview/copy sources. PDFs are archived as bytes and not rendered or executed by the app. Do not open untrusted original documents simply because their hashes match.
- The SQLite verifier opens the bounded file privately in immutable, query-only mode with trusted_schema off and checks the events table, then performs a fixed query. It executes no SQL from users. The editor reconstructs its writable ledger from canonical records. Native dependency parsers still require ordinary patching; this is not a sandbox.
- Poster SVG and PNG/PDF render only canvas pixels and vector content; the editable SVG carries alt text and visible content. Placed images are re-rendered and source PNG text/ICC metadata is not copied into the rendered image. PDF can show software/creation metadata. Evidence exports expose titles, actual source copies or thumbnails, project notes, device times, and previous changes, including deleted material in the archive. No export initiates network traffic. Originals may have embedded private metadata.
